# Security, privacy and deployment boundaries

- **Research-only**: No integration with physical infrastructure, industrial control systems, remote endpoints, OT/ICS networks, vulnerability feeds, or procurement systems. Never connect a prototype to production infrastructure.
- **Storage**: Browser localStorage holds the study on the current origin; it is not encrypted, does not support access controls, and can be read by someone with browser/profile access. Export JSON backups and protect them appropriately. Do not input classified data, credentials, facility configurations, exact vulnerability details, personally identifiable records, or nonpublic operational topology.
- **Untrusted input**: JSON imports are limited to 1 MB and validated against constrained types, values and graph references. User-provided text is HTML-escaped when rendered. DOM uses no external scripts or CDNs. Raw report exports are user-supplied untrusted content; review before further processing.
- **Offline behavior**: No analytics, external API calls, or AI inference. All model execution is deterministic and local. The included server only serves static files and binds to 127.0.0.1 by default.
- **Hosting**: There is no login, tenant isolation, external storage, audit log, or security review. Do not use this as a shared multiuser or public-facing system for real data. Any eventual hosted version needs a separate threat model, authenticated backend, privacy policy, security scanning, secure deployment, incident response, provenance controls and independent penetration testing.
- **Disclosure**: For vulnerabilities in this sample project, do not post sensitive data or working exploit details in public issues. Reach the maintainer privately via their GitHub profile contact method.
